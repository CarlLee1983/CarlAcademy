# CarlAcademy 網站設計

本文件是網站介面的設計交接，屬於專案內部文件，不納入網站頁面、導覽或搜尋。需求與架構邊界以 [PLAN.md](../PLAN.md#靜態文件站架構) 為準；本文件只規範畫面、元件、視覺與互動。

## 首頁定稿：紙雕小卡（2026-11-06）

使用者以「就先以這樣做收尾上線佈署」接受 v10 手機優先原型，並授權正式整合與部署。首頁以本節取代下方 v7／v6 的首頁規則；主題與文章頁沿用教材圖解。

- 手機單欄、701px 起雙欄；900px 起採桌面閱讀尺度，版心最大 1104px。紙雕為縮圖，保留完整主題標題、篇數、摘要與實際首篇閱讀入口。
- 桌面主題 24px、摘要 16px／1.8、閱讀入口 15px；手機主題 20px、摘要 15px、閱讀入口 14px。次要文字混合 ink 與 muted，提高深淺色對比。
- 閱讀入口使用書頁／書籤 SVG 與淡藍底座，篇數為低對比標籤；不使用斜上箭頭。首頁連結包括 hover 均不帶下劃線，改用顏色、底色與可見鍵盤焦點表示狀態；文章正文連結不受影響。
- 紙雕圖集是概念插畫，不是技術架構圖；以 WebP 優化，自託管，不要求外部圖片服務。首頁專屬樣式收斂於 `src/styles/home.css`，共用頁首、搜尋與外觀功能保留。
- 本機原型僅供視覺參考；正式版以 Content Collections 產生篇數和連結，不帶比較列、iframe、原型路徑。

### 字體與字級

- 內文使用 Noto Sans TC（400／500／600／700）。標題、數字與標籤使用 Space Grotesk（400／500／700），中文自動回退 Noto Sans TC。程式碼使用系統等寬字體 `ui-monospace`。
- 兩套字型皆為 OFL 授權，自行託管並子集化，不從外部 CDN 載入。
- 字級共五級：14／16／24／64／112。
  - 112：首頁與主題頁標題。
  - 64：文章標題、首頁主題名、序數。
  - 24：h2 與文末導覽。
  - 16：正文。
  - 14：標籤、目錄、表格。
  - 1050px 以下，112 降為 72；700px 以下，各頁標題統一 40。
- 正文行高 1.7。標題使用負字距：112 為 -5px，64 為 -2px。

### 版面與間距

- 間距以 8 為單位，必要時用 4。內容最大寬度 1440，左右邊距在桌面為 48，1050px 以下為 32，700px 以下為 24。
- 文章版面使用兩欄格線：200px 目錄、64px 間距、680px 正文（中文約 42 字一行）。1050px 以下改為 168px 目錄與 600px 正文。
- 表格與程式碼可以超出正文欄，往右延伸到 `min(880px, 版面寬 − 264px)`。以 container query 依文章版面寬度計算，不依視窗寬度。
- 色塊延伸到視窗兩側全寬，內容仍對齊版面格線。原型做法是 `box-shadow: 0 0 0 100vmax` 加 `clip-path: inset(0 -100vmax)`。

## 圖解

文章中的圖解改由內容端以 **SVG** 製作，不使用 ASCII 框線字元，也不使用生成的點陣圖（2026-11-03 決定）。SVG 的來源格式尚未決定，見下方未決事項。圖解須符合以下規格：

- 只使用上述色彩 token：以 `currentColor` 或 CSS 變數著色，深淺模式都要正確。一張圖只用一個強調色，標出主要路徑。
- 文字使用網站字體。在 680px 正文寬度下，最小字級 14px。
- 以由上往下的流向為主，在 390px 寬度下仍可閱讀；確實需要橫向展開的圖，手機上提供點擊放大。
- 每張圖都有圖說（`figure` 與 `figcaption`）和替代文字。正文要保留等效的文字說明，因為搜尋索引不會讀取圖中的文字。

## 驗收情境

1. 在 1440×900 開啟「Elastic Load Balancing 與 CloudFront」：首屏要讀得到正文，正文起點約在 610px 以內。
2. 在 1440 寬捲動「交易與隔離」：目錄固定不動，並標示目前段落；頁頂進度線隨捲動增加；「隔離等級」表格寬於正文欄，每列不換行。
3. 讀到文末：鈷藍收尾帶不遮擋目錄，可以前往下一篇。
4. 在 390×664 開啟「容器編排與運算容量」：開場只有圖號與標題，提要成為正文第一段；表格顯示為卡片，切換成原表格時畫面不跳動。
5. 手機上捲過開場：閱讀列出現；點「目錄」開啟面板，焦點移入面板；選擇段落後面板關閉並跳到該段，標題不被閱讀列遮住。
6. 手機上的超寬程式碼：右緣有捲動提示，「換行」可以切換，「複製」可以取得原文。
7. 淺色、深色與跟隨系統三種外觀都正確；64 篇文章在 390 與 1440 寬下都沒有水平溢出。
8. 減少動態設定下沒有動畫；全程可以用鍵盤操作，焦點清楚可見。

## 實作順序建議

1. Astro 骨架：版面、色彩 token、字型子集、頁首與頁尾、明暗切換。
2. 文章頁：Content Collections、網址對應、Markdown 管線（含表格 `data-label` 與程式碼框結構）、目錄、收尾帶。
3. 首頁與主題頁。
4. 漸進增強：目前段落、進度、表格切換、程式碼工具、手機閱讀列與目錄面板。
5. Pagefind 搜尋對話框與各種狀態。

## 未決事項與驗證缺口

- **SVG 圖解的來源格式**：手寫 SVG 檔，或 Mermaid／D2 在建置時轉成 SVG。這是依賴選擇，需經規劃入口決定。網站首版不因此阻塞，可以先用過渡處理。
- **首頁起點文字缺空格**：v3 原型的字串把「從」＋標題＋「開始」直接相接，出現「從認識 Linux開始」這種少空格的情況。正式版要處理中英文之間的間距。
- **設計端尚未驗證**：
  - 實機測試（iOS Safari、Android Chrome）。
  - 200% 文字縮放。
  - 真人試讀。

  原型的檢查只在 Chromium 模擬中進行（桌面 1440、手機 390，淺色與深色），內容包括版面、溢出、互動與 token 對比計算。
- **視覺接受與互動驗證分開記錄**：使用者接受的是畫面設計，不等於已完成可用性測試。
