# 快取與資料存取架構：內容規劃

2026-11-06 選定為下一個核心主題。接續已完成的分散式系統（18 篇）與事件驅動架構（12 篇），本主題深入探討應用層快取、記憶體管理、異常防禦、Redis 深度模型與多層快取一致性。全系列規劃 12 篇，完成狀態由[公開索引](../caching/README.md)維護。

## 主題邊界

本主題要回答：
如何以記憶體換取讀取延遲與吞吐，同時有效控制資料過期、並行不一致，以及極端流量下的單點擊穿與系統骨牌式失效？

讀者需具備基本程式開發、HTTP 請求回應與關聯式資料庫基本交易概念。
- 與 [關聯式資料庫](../relational-databases/README.md) 的分工：資料庫是真實資料源（System of Record），維護實體完整性與交易隔離；快取則是在應用存取路徑上卸載資料庫負載，但引入雙寫視窗與暫態不一致。
- 與 [電腦網路](../networking/README.md) 的分工：RFC 9111 HTTP 快取（Cache-Control、ETag、304 協商）與 CDN 負責在邊緣節點攔截外部流量；本主題聚焦後端架構（行程內快取、集中式 Redis、多層快取與快取無效化協調）。
- 與 [分散式系統](../distributed-systems/README.md) 的分工：引用時間、租約（Lease）、複寫與 CAP/PACELC 邊界；本主題專注於快取拓撲下的暫態不一致收斂與 Fencing 防禦。
- 與 [訊息佇列與事件驅動架構](../event-driven-architecture/README.md) 的分工：以 CDC（Change Data Capture）或事件發布作為快取非同步失效的手段，解決資料庫與快取雙寫的原子性缺口。

## 貫穿案例

沿用文章閱讀與內容發布服務（Article Publishing & Reading Access Service）：
- **讀取工作**：文章正文高頻閱讀、作者公開個人檔案、熱門排行榜與閱讀次數累加。
- **變更工作**：作者編輯文章重新發布、修改個人簡介、讀者按讚或點擊閱讀。
- **異常與邊界挑戰**：
  - 惡意爬蟲遍歷無效的文章 ID 狂掃後端（快取穿透）。
  - 熱門文章快取過期瞬間，上萬請求併發湧入資料庫回填（快取擊穿／Thundering Herd）。
  - 批次文章設定相同 TTL 造成同一秒集體失效，或 Redis 單點故障重啟（快取雪崩）。
  - 編輯文章後，資料庫已更新但快取保留舊值，或先刪快取後被慢讀取回填舊資料（雙寫競爭與延遲雙刪）。
  - L1 本機記憶體與 L2 Redis 叢集之間的資料不同步。

## 建議閱讀主線

全系列共 12 篇，分為五個階段推進：

| 順序 | 文章方向 | 核心問題與案例推進 | 可觀察的完成判準 |
|---|---|---|---|
| 01 | 記憶體階層與快取代價 | 為什麼需要快取？以記憶體換時間背後伴隨什麼複雜度與邊界代價？ | 列出 CPU 快取、RAM、SSD 與網路請求的延遲數量級差異，指出不適合快取的資料特徵，不把快取當成萬靈丹。 |
| 02 | 讀寫模式：Cache-Aside 到 Write-Behind | 讀寫資料時，應用程式、快取與資料庫的先後順序該如何安排？ | 畫出 Cache-Aside、Read-Through、Write-Through 與 Write-Behind 的時序圖，指出各自的資料遺失與不一致風險。 |
| 03 | 過期策略、TTL 與清除機制 | 資料過期（Expire）與逐出（Evict）有何不同？TTL 倒數如何實現？ | 區分主動定時抽樣清除與被動惰性清除（Lazy Expiration），說明 TTL Jitter 為何必要。 |
| 04 | 快取穿透、空值快取與布隆過濾器 | 當查詢惡意鎖定不存在的資料時，如何避免流量直擊資料庫？ | 比較空值快取（Cache Null）與 Bloom Filter 的演算法複雜度、記憶體開銷與誤判率（False Positive）邊界。 |
| 05 | 快取擊穿、熱點 Key 與防互斥鎖 | 熱點文章過期引發 Thundering Herd 時，如何壓制瞬間併發？ | 分析分散式互斥鎖（Mutex / SingleFlight）、邏輯過期非同步回填，與 Facebook Lease 租約機制的防禦效果。 |
| 06 | 快取雪崩與彈性架構 | 大量快取集中失效或快取服務重啟時，如何避免資料庫骨牌式崩潰？ | 設計隨機化 TTL 抖動、快取叢集高可用、資料庫連線隔離、Circuit Breaker 熔斷降級策略。 |
| 07 | 記憶體逐出演算法：LRU 到 W-TinyLFU | 記憶體用盡時，誰該被剔除？如何兼顧突發熱點與長期高頻？ | 比較 FIFO、LRU（雜湊雙向鏈結串列）、LFU（計數與衰減）與 Window TinyLFU，說明快取污染（Cache Pollution）的成因與解法。 |
| 08 | 記憶體碎片、序列化與空間預算 | 為何存入 100MB 資料，Redis 卻耗用 300MB 記憶體？ | 解析 jemalloc 內部與外部碎片、`used_memory_rss` 水位、BigKey 危害，以及 JSON、Protobuf、MsgPack 序列化代價。 |
| 09 | Redis 資料結構深度剖析與執行模型 | Redis 為何能維持數十萬 QPS？單執行緒事件循環與底層結構如何設計？ | 拆解 SDS、Listpack、Dict、SkipList 結構；說明 I/O 多路複用（epoll）與單執行緒執行邊界、Pipeline 與 Lua 原子性。 |
| 10 | Redis 持久化、複寫與高可用性 | 記憶體資料如何防禦重啟遺失？主從複製與 Cluster 如何達成可用性？ | 分析 RDB fork COW 開銷、AOF 刷盤策略、PSYNC 增量複製、Sentinel 容錯裁決與 Cluster 16384 Hash Slots 路由。 |
| 11 | 快取與資料庫一致性：更新策略與 CDC | 先更 DB 還是先刪快取？並行競爭下的不一致如何收斂？ | 分析先刪快取 vs 先改 DB 的並行時序競態；評估延遲雙刪與基於 Binlog / CDC 的可靠非同步失效機制。 |
| 12 | 多層快取整合案例：文章服務實踐 | 如何整合 L1 本機記憶體、L2 Redis 與 L3 資料庫，建立端到端架構？ | 組裝完整三層架構：L1 本機快取、L2 分散式快取、L3 資料庫，配合失效廣播、關鍵監控指標與故障演練矩陣。 |
