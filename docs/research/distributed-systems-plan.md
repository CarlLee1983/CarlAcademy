# 分散式系統內容規劃

本系列以「跨程序、跨主機的操作如何在延遲與故障下維持可說明的行為」為主軸，先建立問題與保證，再引入協調機制，最後組合成完整設計。

規劃日期：2026-11-04。本文是內部編寫規劃，不納入公開網站。文章完成狀態由[公開主題索引](../distributed-systems/README.md)維護；來源查證集中於[研究筆記](distributed-systems-sources.md)，各文章仍在相關論述旁直接引用來源。

## 讀者、目標與範圍

讀者能理解一次 API 請求、資料庫交易與基本網路通訊，不要求讀過分散式演算法論文。需要的既有背景連回本站文章；不要求先學完全部網路、AWS 或資料庫內容。

讀完主線後，讀者應能追蹤一次操作的請求、狀態與副作用，說明故障下哪些結果已知、哪些仍不確定；能依需求選擇一致性與協調方式，也能提出可觀察的反例與驗證方法。學習成果不是記住產品分類表或某種架構樣板。

範圍涵蓋 crash／recovery、網路延遲與分割、並行更新及過載。拜占庭模型先交代與上述模型的差異，不延伸區塊鏈與 BFT 協定推導；完整 Paxos 證明、多區產品部署、串流運算平台與特定框架操作留待後續。故障容錯也不能替代身分驗證、授權或資料保護。

## 貫穿案例與用語

使用自創的「文章匯出服務」：使用者建立匯出工作，服務保存工作狀態，worker 產生檔案，再發出完成通知。案例隨篇章逐步增加元件，避免一開始就堆滿佇列、分片與協調服務。

- **業務意圖**：使用者要產生某一份匯出；同一意圖可有多次傳送嘗試。
- **請求識別**：追蹤單次網路嘗試；不自動等於冪等鍵。
- **操作識別／冪等鍵**：在明訂範圍與保留期內識別同一意圖。
- **工作識別**：服務建立後可持續查詢的業務物件識別。
- **事件識別**：用於辨認同一個事件的重複投遞；與匯出意圖分開。

每次增加元件，都先提出上一階段無法解決的問題。例子中的保證是案例明訂條件；不得把概念流程寫成已實測的產品能力。

## 篇章銜接與既有主題分工

- **API**：沿用[逾時、重試與冪等性](../api/timeouts-retries-and-idempotency.md)、[非同步操作](../api/long-running-operations-and-async-apis.md)與 [Webhook](../api/webhooks-and-event-callbacks.md)的對外契約。本系列補內部原子邊界與故障歷程；不重列 HTTP 方法或狀態碼表。
- **關聯式資料庫**：引用[交易與隔離](../relational-databases/transactions-and-isolation.md)、[MVCC 與鎖定](../relational-databases/locking-and-mvcc.md)。本系列研究多節點或多服務的保證，不把單資料庫 ACID 當成端到端保證。
- **網路**：引用 [TCP](../networking/tcp-connection-and-flow-control.md)、[負載平衡](../networking/load-balancing-and-reverse-proxy.md)與診斷知識。本系列討論應用觀測與狀態，TCP 有序傳輸不能推成業務操作只做一次。
- **AWS**：產品用來對照概念，服務專屬承諾連回 [SQS／SNS／EventBridge](../aws/sqs-sns-and-eventbridge.md)等文章；不以某一雲端的限制定義通用模型。
- **後續候選主題**：事件驅動架構承接事件治理與 schema 演進；快取主題承接失效策略；可靠性工程承接完整 SLO、容量與事故流程；並行處理主題承接單程序同步與語言記憶體模型。本系列仍保留理解端到端正確性必需的共通概念。

每篇開頭交代承接的問題，結尾交代仍未解決的問題。已完成文章互相連結；待寫文章僅在索引列標題與狀態，不建立失效連結。全文不要求讀者先閱讀尚未完成的篇章才能理解當篇結論。

## 資料蒐集與文章驗收

1. 為每篇建立「問題 → 模型與前提 → 來源 → 例子 → 反例或限制」鏈。先讀原始論文、標準或產品官方文件；同一名詞在不同模型中含義不同時直接說明。
2. 所有數值推算明列假設；概念歷程標為自創例子。只做文件查證就寫明未執行實驗；產品文件的查閱日期與固定論文年份分開。
3. 每篇至少有一個可逐步追蹤的歷程及一個常見錯誤推論。術語第一次出現附英文；新概念不得依賴後文尚未說明的機制。
4. 依主線檢查依賴：01–04 的問題與觀測，支撐 05–08 的契約；契約支撐 09–12 的協調；協調邊界支撐 13–16 的組合；17–18 回查所有承諾。
5. 每個交付批次更新公開索引、根目錄入口與本規劃的進度連結；執行專案要求的完整驗證，檢查根路徑與子路徑的公開頁面、閱讀順序、連結、搜尋及內部文件排除。內容正確性另以來源與歷程審核，不能拿網站建置成功代替。
