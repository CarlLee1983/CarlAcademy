# 分散式系統知識索引

從一次遠端操作的不確定結果出發，逐步理解多份資料的一致性、共同決定的形成，以及跨服務工作的正確性邊界。
主線以文章匯出服務貫穿，先說明問題與所需保證，再引入機制與取捨，不預設採用微服務或特定雲端產品。

**目前狀態：完整主線規劃 18 篇，已撰寫第一階段 4 篇，其餘 14 篇待撰寫。**
查證日期：2026-11-04。已寫文章依原始論文、Linux man-pages、gRPC 與 AWS 官方工程文件整理；查證範圍與來源見各篇。案例均為概念推演，未執行分散式部署、壓力或故障注入實驗。

## 先備知識與閱讀方式

讀者需能理解一次請求與回應、基本網路通訊及資料庫交易；不要求先學完其他主題，也不要求先讀演算法論文。遇到對應概念時，可回查 [API](../api/README.md)、[電腦網路](../networking/README.md)與[關聯式資料庫](../relational-databases/README.md)。

每一階段承接前一階段留下的問題。建議第一次依主線閱讀；已有背景的讀者可直接查閱當篇的模型、例子與限制。本系列主要處理程序停止與恢復、通訊異常、並行操作與過載；拜占庭容錯、區塊鏈與特定產品部署不在目前主線。

## 第二階段：多份狀態能承諾什麼（待撰寫）

05–08 接續第一階段的觀測與因果，先訂讀寫契約，再檢查複寫與分割下的行為：

5. **一致性模型與操作歷程**：線性、循序、因果與最終一致性，以及 session guarantees；區分副本一致性與交易隔離。
6. **複寫、確認與故障切換**：單主、多主、無主，同步與非同步複寫，以及已確認寫入在切換時的風險。
7. **Quorum、版本與衝突修復**：讀寫集合交集、並行版本、讀修復與反熵；說明 quorum 算式不能單獨證明線性一致。
8. **網路分割與 CAP 的適用邊界**：以具體讀寫歷程理解分割期間的一致性與可用性取捨，避免三選二口號。

## 第三階段：共同決定與安全的所有權（待撰寫）

09–12 用上一階段的契約解釋協調為何必要，然後處理持有者停止與恢復的風險：

9. **共識、安全性與不可能性邊界**：共識條件、狀態機複寫與 FLP 的時序前提。
10. **Raft 與複寫日誌**：任期、選舉、提交與套用，並說明讀取及客戶端重試的額外條件。
11. **租約、分散式鎖與 fencing**：舊持有者恢復後為何仍可能寫入，以及受保護資源如何拒絕過期持有者。
12. **分片、路由與資料搬遷**：資料放置、熱點、再平衡及搬遷期間的寫入所有權；區分資料分片與網路分割。

## 第四階段：跨越單一原子邊界（待撰寫）

13–16 從單一交易與協調的邊界出發，研究跨服務的提交、補償、投遞與合併：

13. **原子提交與兩階段提交**：prepare、持久決策、in-doubt 與阻塞；區分原子提交、共識與隔離。
14. **Saga 與業務補償**：局部交易、編排與協同、補償失敗與人工介入；不能把補償當成完整 rollback。
15. **投遞語意、Outbox 與 Inbox**：資料庫與事件雙寫、relay 重送、消費去重，以及 exactly-once 的具體範圍。
16. **收斂、合併與 CRDT**：哪些資料可以安全合併，以及哪些業務不變式仍需要協調。

## 第五階段：用證據檢驗完整設計（待撰寫）

17–18 回收前面所有承諾，從故障歷程檢驗端到端設計：

17. **分散式觀測、故障注入與歷程驗證**：追蹤識別、trace、log、metric、歷程 checker 與可重現故障；區分測試和證明。
18. **整合案例：可靠的文章匯出服務**：從最小可行版本逐步增加機制，列出不變式、狀態轉移、故障矩陣、恢復與仍需人工處理的情況。

## 與既有主題的分工

- [API 共通知識](../api/README.md)：負責呼叫者看見的輸入、輸出、錯誤與重送契約；本主題補履行契約所需的狀態與協調。
- [關聯式資料庫](../relational-databases/README.md)：負責 SQL、約束與單資料庫交易；本主題說明跨節點與跨服務時保證如何改變。
- [電腦網路](../networking/README.md)：負責封包與傳輸協定；本主題研究應用狀態，不能把連線可靠等同業務效果只做一次。
- [AWS](../aws/README.md)：提供服務專屬能力與限制；本主題先建立通用模型，不以產品名稱替代保證。
- [Web 應用資安](../web-security/README.md)：處理攻擊、信任與權限；容錯與一致性不能替代這些防護。
