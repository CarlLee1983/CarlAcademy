# CarlAcademy 靜態文件站首版

Status: completed

## Problem Statement

CarlAcademy 已累積 Linux、AWS、API、關聯式資料庫及 Web 應用資安五個主題的 Markdown 文件，但尚無正式網站。讀者需要能從主題建立認識，也能直接查找概念、服務及問題，並在桌面或手機上閱讀、搜尋及沿相關連結補足背景知識。

作者需要沿用既有內容與主題索引，避免維護第二份網站文章；公開網址須穩定，建置產物須能由一般靜態伺服器提供，保留更換託管平台的能力。既有介面設計已接受，尚待實作與驗收。

## Solution

建立繁體中文為主的靜態文件站，提供網站首頁、主題索引、知識文章及全站搜尋。首頁幫助讀者找到主題與閱讀起點；主題索引維持既有閱讀安排；文章提供主題切換、文件導覽、本文目錄及前後篇入口。搜尋涵蓋標題與正文，結果包含文章名稱、主題與命中摘要。

採用已確認的 Astro、Content Collections 與 Pagefind 架構，以及結構 A、視覺「8 海報封面」v6 的定稿。正文與基本導覽以靜態 HTML 提供，互動採漸進增強；根路徑與子路徑建置皆須通過相同驗收。

## User Stories

1. As a 首次造訪的讀者, I want 首頁說明 CarlAcademy 的定位與內容範圍, so that 我知道這個網站能幫助我理解哪些知識。
2. As a 讀者, I want 從首頁找到五個主題入口, so that 我可以依當下需要選擇閱讀方向。
3. As a 初學某主題的讀者, I want 看到主題說明、文件數與閱讀起點, so that 我能選擇適合的第一篇文件。
4. As a 讀者, I want 主題索引依既有安排列出標題與摘要, so that 我理解文件範圍與建議閱讀順序。
5. As a 讀者, I want 各主題可以獨立閱讀, so that 我不必先完成其他主題才能使用網站。
6. As a 讀者, I want 瀏覽現有所有公開文章, so that 既有知識不會在建站時遺漏。
7. As a 讀者, I want 直接開啟或重新整理文章網址, so that 我能收藏及分享特定文件。
8. As a 讀者, I want 中文標題更新後網址仍穩定, so that 我的收藏不因文字修改失效。
9. As a 讀者, I want 文件間的相關連結與段落錨點有效, so that 我能回查背景知識及定位段落。
10. As a 讀者, I want 隨時切換主題, so that 我能跨主題查找相關內容。
11. As a 文章讀者, I want 查看目前主題的文件清單, so that 我知道目前文件與其他文件的關係。
12. As a 文章讀者, I want 查看本文目錄並跳到段落, so that 我能快速找到需要的說明。
13. As a 文章讀者, I want 知道目前段落與閱讀進度, so that 我能在長文章中保持方向。
14. As a 文章讀者, I want 從文末開啟上一篇或下一篇, so that 我能依主題安排持續閱讀。
15. As a 查找資料的讀者, I want 搜尋文章標題與正文中的繁體中文詞, so that 我能從概念找到文件。
16. As a 查找資料的讀者, I want 搜尋英文技術名詞, so that 我能找到工作中遇到的術語。
17. As a 搜尋使用者, I want 結果顯示主題、文章名稱及命中摘要, so that 我能判斷哪篇符合問題。
18. As a 搜尋使用者, I want 清楚區分空輸入、無結果與索引載入失敗, so that 我知道接下來應採取的動作。
19. As a 搜尋使用者, I want 索引載入失敗時可以重試, so that 暫時失敗不會迫使我離開網站。
20. As a 手機讀者, I want 主題導覽與文件清單適當收合, so that 畫面不被全站連結占滿。
21. As a 手機讀者, I want 文章開場精簡且提要出現在正文開頭, so that 我能快速開始閱讀。
22. As a 手機讀者, I want 捲過開場後使用閱讀列及章節面板, so that 我無須返回頁首就能切換段落。
23. As a 手機讀者, I want 選取章節後面板關閉且標題不被遮住, so that 我能接續閱讀正確位置。
24. As a 手機讀者, I want 表格預設以帶欄名的卡片呈現, so that 我能在窄螢幕理解每個欄位。
25. As a 需要比較資料的讀者, I want 切回原表格並橫向捲動, so that 我能保留欄列對照關係。
26. As a 閱讀程式碼的讀者, I want 複製原始程式碼, so that 我能保留正確內容與換行。
27. As a 閱讀程式碼的讀者, I want 超寬時看見捲動提示並可切換換行, so that 我能在不同寬度閱讀範例。
28. As a 讀者, I want 選擇系統、淺色或深色外觀, so that 閱讀環境符合我的需求。
29. As a 鍵盤使用者, I want 跳至內容、可見焦點及可操作的搜尋與章節面板, so that 我能完成所有主要閱讀流程。
30. As a 對動態敏感的讀者, I want 網站遵循減少動態偏好, so that 動畫不影響閱讀。
31. As a 停用 JavaScript 的讀者, I want 仍能閱讀正文、表格與基本連結, so that 知識內容不依賴互動程式。
32. As a 讀者, I want 字體、正文寬度及配色符合定稿, so that 長篇閱讀保持清楚且一致。
33. As a 讀者, I want 寬表格與程式碼在各自容器捲動, so that 整頁不會水平溢出。
34. As a 內容作者, I want Markdown 維持唯一文章來源, so that 我只需維護一份知識內容。
35. As a 內容作者, I want 使用既有相對連結並在建置時轉成公開網址, so that 本地閱讀與網站閱讀都可成立。
36. As a 維護者, I want 建置檢查必要資料與網址衝突, so that 無效內容不會靜默產生錯誤網站。
37. As a 維護者, I want 內部規劃、詞彙表、設計交接與 ADR 不進入公開輸出, so that 讀者只會看到公開知識內容。
38. As a 維護者, I want 根路徑與子路徑建置的連結、資源及搜尋一致有效, so that 我可依託管需求選擇部署位置。
39. As a 維護者, I want 在一般靜態伺服器驗證完整產物, so that 網站不依賴特定平台的路由補全行為。
40. As a 維護者, I want 可重複的中文與英文搜尋案例, so that 更新內容或工具後能確認搜尋仍可使用。

## Implementation Decisions

- **內容與架構**：採 Astro 靜態輸出、Content Collections 與 Pagefind。既有公開主題的 Markdown 是唯一內容來源，可補少量標題、摘要等頁面資料，不新增人工維護的網站文章副本。
- **責任邊界**：內容載入與 schema 驗證、統一內容查詢、網址與連結解析、靜態路由、共用版型與元件、搜尋索引及建置驗證各自負責既定工作。頁面透過統一內容入口取得主題、文件及索引順序；網址與 base path 由共同規則提供，導覽與搜尋共用。
- **公開範圍**：只載入公開主題索引與文章，另產生網站首頁。內部規劃、詞彙表、ADR、代理設定及網站設計交接不得進入頁面、導覽、搜尋或以原始檔形式混入輸出。現有文章連往內部文件的內容須改成適合讀者的導覽。
- **網址契約**：英文分層路徑與尾斜線；主題索引對應主題首頁，文章沿用目前英文檔名作初始識別。中文標題修改不改網址。建置時將 Markdown 相對連結轉為公開網址，保留段落錨點，檢查衝突與無效連結。根路徑與子路徑按各次建置設定套用 base path，不承諾同一份產物任意搬移。未來已發布網址變更須保留轉址，目前不假定有既存外部網址遷移。
- **導覽與順序**：依主題索引安排文件，不以更新日期倒序。文章提供全站主題切換、目前主題文件清單、本文目錄及依相同順序的前後篇導覽；邊界文件不產生無效前後篇連結。
- **設計契約**：依已接受的結構 A 與「8 海報封面」v6 實作，完整視覺數值與互動細節沿用既有設計交接，不另行探索視覺方向。包含鈷藍全寬開場、首頁主題列、主題文件列、文章雙欄閱讀版面、文末收尾帶、頁首及頁尾。
- **文字與外觀**：自行託管並子集化 Noto Sans TC 與 Space Grotesk，保留授權；程式碼使用系統等寬字體。使用定稿色彩、字級、寬度、間距與響應斷點。提供系統、淺色、深色外觀，預設跟隨系統。首頁起點文字須處理中英文間距。
- **表格與程式碼**：建置時輸出工具列結構及表格欄名資料；手機表格卡片以 CSS 成立。原表格切換、程式碼複製與超寬換行採漸進增強；換行按鈕只在內容超寬時提供，複製取得原文，尚未捲到底時顯示右緣提示。桌面寬內容依文章容器延伸，手機容器可延伸至螢幕兩側，避免整頁溢出。
- **閱讀互動**：桌面固定本文目錄、目前段落及頁頂進度；手機捲過開場後顯示閱讀列，章節面板使用原生 dialog，選取段落後關閉並定位，保留正確焦點行為與標題避讓。手機文章提要置於正文開頭，主題導覽改為下拉，文件與本文目錄可收合。
- **搜尋**：對完整公開 HTML 建立 Pagefind 索引，涵蓋標題與正文、排除重複導覽文字。結果具備文章名稱、主題與命中摘要；搜尋對話框包含結果數、空輸入、無結果、載入失敗及重試狀態。選定版本與建置方式須實際支援中文斷詞，以查詢案例驗證品質，不以工具支援宣告替代驗收。
- **漸進增強與無障礙**：正文、連結與表格卡片不依賴 JavaScript；搜尋在瀏覽器執行。第一個焦點為跳至內容，互動元素有可見焦點，觸控目標與目錄連結大小依設計交接；減少動態時關閉動畫。字型、資源與搜尋載入均遵循 base path。
- **圖解**：首版保留現有框線圖原排版並允許容器橫向捲動。後續圖解採符合網站 token、圖說、替代文字及正文等效說明的 SVG；來源格式仍未決，不在此 spec 選擇新的圖解工具。
- **參考邊界**：參考 CarlStack 的內容與版型分層，不直接複製部落格日期排序、固定根路徑或非本站需求。定稿原型僅作參考，不搬入樣張切換列、參數式路由、示範搜尋、原型頁尾或以 JavaScript 移動文末導覽的寫法；repo 內另一份方向比較稿不是定稿。

## Testing Decisions

- **已確認的主要測試邊界**：正式建置產物透過一般靜態伺服器提供的網站。檢查讀者可觀察的行為及公開輸出，不綁定元件內部結構、私有方法或生成檔案排列。可由同一套驗收入口協調輸出檢查與瀏覽器操作，避免散布重複測試邊界。
- **既有測試先例**：目前 repo 以 Markdown 文件為主，尚無正式網站程式、套件設定或網站測試。既有定稿原型的 Chromium 模擬證據與設計情境可作驗收參考，不代表正式產物已通過。先建立上述產物層的測試入口，不假定已有可沿用的測試框架。
- **覆蓋範圍**：檢查首頁、目前五個主題索引與 64 篇文章全部可瀏覽。內容增加時由實際公開清單推導覆蓋，不把 64 寫成永久上限。
- **網址與內容完整性**：直接開啟及重新整理深層文章；檢查跨主題連結、相對連結轉換、錨點、索引順序與前後篇。以建置輸出及公開網址驗證必要資料、重複網址及無效目標不會靜默成功。檢查標題變更與網址穩定的契約。
- **部署路徑矩陣**：分別為根路徑及一個非空子路徑建置與提供服務，重複驗證首頁、深層網址、導覽、字型、資源、搜尋模組與索引。伺服器不提供平台特有的副檔名補全。
- **公開輸出邊界**：檢查公開頁面、導覽、搜尋結果及輸出檔案，確認內部管理文件與原始檔未混入。
- **搜尋品質與狀態**：從既有文章選定可重複的繁體中文詞與英文術語，記錄預期文章，驗證標題和正文命中、主題及摘要、結果導向與子路徑載入。操作空輸入、無結果、索引載入失敗及重試；重試後能回復搜尋。
- **Markdown 渲染**：以實際管線與文件涵蓋中文標點旁的粗體、數字範圍、表格、程式碼及標題錨點，透過呈現結果檢查，不能只證明 parser 有回傳內容。
- **桌面閱讀**：在 1440×900 開啟 Elastic Load Balancing 與 CloudFront 文件，正文起點約在 610px 以內；捲動交易與隔離文件時目錄固定、目前段落與進度更新，隔離等級表格依定稿延伸且列內不換行。文末收尾帶不遮擋目錄且導覽有效。
- **手機閱讀**：在 390×664 開啟容器編排與運算容量文件，驗證精簡開場、導言、表格卡片及原表格切換，工具列位置穩定。驗證閱讀列出現條件、面板開啟焦點、選取後關閉與定位、標題不被遮擋；驗證超寬程式碼捲動提示、換行與原文複製。
- **視覺與溢出**：既有全部文章在 390 與 1440 寬度及淺深外觀下不得造成整頁水平溢出；寬內容可在自身容器捲動。檢查系統外觀跟隨、手動外觀、定稿版面與字體載入。
- **無障礙與韌性**：用鍵盤完成主題切換、搜尋、閱讀導覽與面板操作，檢查焦點可見、跳至內容及焦點回復。減少動態時無動畫；停用 JavaScript 後正文、表格卡片與基本導覽仍可閱讀使用。
- **尚無驗證證據的情境**：iOS Safari、Android Chrome 實機、200% 文字縮放及真人試讀尚未驗證。交付須明確區分已執行結果與未驗證範圍，不能以 Chromium 模擬或視覺接受代替這些證據。
- **交付證據**：記錄實際建置與驗收命令、來源版本、環境、覆蓋範圍及結果；不得將本 spec 或既有設計接受描述為網站已完成驗收。

## Out of Scope

- 實際發布、選定託管平台、網域、平台專用整合與分析追蹤。
- 會員、付費、進度記錄、測驗、練習系統、互動學習地圖、留言及互動實驗室。
- 新增一整套知識內容、複製多語言概念文件或調整既有主題定位。
- 重新設計已定稿介面，或將方向比較稿當作正式設計。
- 將內部管理文件公開，或維護第二份網站文章來源。
- 全面重繪現有圖解、選擇 SVG 來源工具；首版採已約定的過渡呈現。
- 假定已有外部網址需要遷移，或保證同一建置產物可在不同 base path 任意搬移。
- 安裝網站依賴、實作網站、commit、push 或部署；本次工作僅產出 spec。
